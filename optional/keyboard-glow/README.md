# Keyboard Glow

Whole-keyboard lighting for the ASUS TUF A14 FA401EA on Omarchy 4 / Hyprland Lua.

## Install the optional bundle

This bundle is separate from the general desktop staging script. Review and
back up existing files before copying. The FA401EA model override was verified
with asusctl 6.4.0; it is not a capability declaration for other ASUS models.

Runtime dependencies are Omarchy, asusctl/asusd, Python with `dbus` and
`gi.repository` (GLib and GLibUnix), `gum`, and `notify-send`. Music additionally
uses `pactl` and `parec` against the desktop's PulseAudio-compatible server.
These dependencies were already available on the verified installation.

From the repository root, copy the files:

```sh
install -Dm755 optional/bin/glow "$HOME/.local/bin/glow"
install -Dm755 optional/bin/asus-hotkey "$HOME/.local/bin/asus-hotkey"
install -Dm644 optional/keyboard-glow/glow.py "$HOME/.local/share/keyboard-glow/glow.py"
install -Dm644 optional/keyboard-glow/README.md "$HOME/.local/share/keyboard-glow/README.md"
install -Dm644 optional/bash/keyboard-glow.bash "$HOME/.config/keyboard-glow/shell.bash"
install -Dm644 optional/hypr/asus-bindings.lua "$HOME/.config/hypr/asus-bindings.lua"
install -Dm644 optional/hypr/keyboard-glow.lua "$HOME/.config/hypr/keyboard-glow.lua"
install -Dm644 optional/systemd/keyboard-glow.service "$HOME/.config/systemd/user/keyboard-glow.service"
```

Load these modules once, after the usual Omarchy bindings, in this order:

```lua
-- At the end of ~/.config/hypr/bindings.lua (omit an include already present).
dofile(os.getenv("HOME") .. "/.config/hypr/asus-bindings.lua")
dofile(os.getenv("HOME") .. "/.config/hypr/keyboard-glow.lua")
```

`keyboard-glow.lua` replaces the native Aura Fn+F4 binding and adds Shift+Fn+F4.
When adapting an existing configuration, keep only one typing-activity module
include. The ASUS helper also supplies performance-profile bindings; see the
repository's optional ASUS helper instructions for profile notifications.

Add this line to `~/.bashrc.local`, preserving its other contents:

```bash
[[ -r $HOME/.config/keyboard-glow/shell.bash ]] && source "$HOME/.config/keyboard-glow/shell.bash"
```

If asusd does not already expose Static and Breathe for the FA401EA, install its
model entry. If `/etc/asusd/asusd_user_ledmodes.ron` already has other entries,
merge this entry into that file instead of replacing it:

```sh
sudo install -m 0644 --backup=numbered optional/asusd/asusd_user_ledmodes.ron /etc/asusd/asusd_user_ledmodes.ron
sudo systemctl restart asusd
```

Then validate the configuration and start the service:

```sh
hyprctl reload
hyprctl configerrors
systemctl --user daemon-reload
systemctl --user enable --now keyboard-glow.service
glow status
```

The service starts in Candlelight at brightness 2/3 on its first run. An existing
saved selection takes precedence. Restart an already-running service after
updating its Python implementation.

## Controls

- **Fn + F4**: next effect.
- **Shift + Fn + F4**: previous effect.
- Keyboard brightness keys: set the maximum brightness for every effect.
- Brightness zero: all lighting and visual alerts stay off.
- Run **`glow`** in a terminal for a mode picker, or `glow list` for the list.

The service starts with the graphical session. Your selected mode, brightness,
and workspace/battery alert preferences are saved between sessions.

## Modes

| Command | Effect |
|---|---|
| `glow mode static` | Steady light |
| `glow mode breathe` | Smooth breathing generated by the keyboard controller |
| `glow mode heartbeat` | A repeating double pulse |
| `glow mode candle` | Random flicker |
| `glow mode gpu` | A heartbeat that speeds up with GPU utilization |
| `glow mode music` | Brightness follows the current audio output |
| `glow mode battery` | Brightness reflects battery charge; charging adds a pulse |
| `glow mode temperature` | Low below 50°C, medium at 50–69°C, high at 70°C or above, scaled to your brightness ceiling |
| `glow mode typing` | Brighten on typing, then settle down after a few seconds |
| `glow mode focus` | Start a 25-minute focus / 5-minute break timer |
| `glow mode morse` | Repeatedly blink HELLO in Morse code |
| `glow mode off` | Completely off, including visual alerts |

Software effects use Off / Low / Medium / High, so their fades are stepped.
The keyboard's native Breathe mode remains smooth. These are whole-keyboard,
single-colour effects. GPU and temperature modes only read sensors.

Music uses the audio output monitor. It starts only in Music mode, switches
when the default audio output changes, and stops when you select another mode
or lock the session. Audio is processed in memory and is not saved.
Typing sends only a boolean activity signal from Hyprland, at most every
300 ms. The service never receives keycodes or text.

## Temporary messages and alerts

Alerts briefly overlay the selected mode and then restore it. Mode changes
cancel an active alert. Completion and timer alerts take priority over workspace
signals; a new alert of equal or higher priority replaces the current alert.

```sh
glow alert success         # two short blinks
glow alert failure         # three longer blinks
glow morse "HELLO WORLD"   # play once, then restore the current effect
```

Morse accepts up to 80 letters, digits, and spaces. Messages are not saved.

Workspace changes blink the workspace number, up to ten. Connecting power
blinks twice; disconnecting blinks once. Crossing into low battery (15% or
less, unplugged) blinks three times. These are enabled initially:

```sh
glow events workspace off
glow events battery off
# Use "on" to enable either again.
```

## Commands, builds, tests, and local AI

New interactive Bash terminals automatically signal when a command taking at
least ten seconds returns to the prompt. Success blinks twice; failure blinks
three times. Ctrl+C does not generate a failure alert. Command text is never
sent to the lighting service. Shell status and the existing prompt are preserved.

For a command of any duration, including scripts outside an interactive shell:

```sh
glow run -- make
glow run -- npm test
glow run -- ollama run MODEL "Your prompt"
glow run -- lms load MODEL
glow run -- bash -c 'build-command && test-command'
```

The wrapped command retains stdin, stdout, stderr, and its original exit status.
In new Bash terminals, `ollama run ...` is automatically wrapped. A one-shot
request signals when it finishes; an interactive chat signals when the chat
command exits. This does not intercept individual requests in the LM Studio
GUI or other already-running applications. Those can call `glow alert success`
from their own completion hooks.

To enable the shell integration in an existing Bash terminal:

```sh
source ~/.config/keyboard-glow/shell.bash
```

Change the automatic threshold with `KEYBOARD_GLOW_MIN_SECONDS=30`, for example.
The implementation appends to PS0 and prepends a status-preserving prompt hook;
it does not replace the prompt or install a DEBUG trap.

## Focus timer

```sh
glow focus start                 # 25 minutes work, 5 minutes break
glow focus start --work 50 --rest 10
glow status                      # includes remaining time and phase
glow focus stop
```

Work uses dim steady light; breaks use a pulse. A notification and three blinks
announce each transition. It alternates until stopped. Selecting another mode
cancels the timer, so cycling past Focus does not leave a timer running.
Stopping via `glow focus stop` restores the mode selected before Focus.
An unfinished timer restarts at 25/5 after restarting the service; elapsed time
is not saved across service restarts.

## Service and troubleshooting

```sh
glow status
systemctl --user status keyboard-glow
journalctl --user -u keyboard-glow -n 30
systemctl --user restart keyboard-glow
```

The service pauses effects while locked or away from the active graphical
session and stops music capture. It resumes the selected effect when active.
It restores the lighting it found at startup when stopped normally.

Frame updates use logind's session brightness API and do not save firmware
settings or rewrite asusd's configuration on every frame. Only native effect
changes use asusd. Runtime brightness control uses the active login session and
does not require additional sudo permissions.

To stop autostart and return control to the regular ASUS tools:

```sh
systemctl --user disable --now keyboard-glow
```

Brightness keys fall back to the original helper when the service is absent.
Fn+F4 requires the service. Remove the `keyboard-glow.lua` include and reload
Hyprland to return it to the native bindings supplied by `asus-bindings.lua`.
Remove the shell integration include from `~/.bashrc.local` if no longer wanted;
new terminals will then use the original Ollama command and prompt setup.

Files: `~/.local/share/keyboard-glow/glow.py`, `~/.local/bin/glow`,
`~/.config/keyboard-glow/shell.bash`, `~/.config/hypr/keyboard-glow.lua`,
`~/.config/systemd/user/keyboard-glow.service`.
Settings: `~/.local/state/keyboard-glow/state.json`.
Temporary control sockets and shell timestamps: `$XDG_RUNTIME_DIR/keyboard-glow/`.

## Verification

Verified on 2026-09-11:

- Twelve effect/composition tests pass, including alert restoration, priority,
  brightness limits, focus cancellation, Morse spacing, and inactive-session handling.
- All twelve modes were exercised through the running service without hardware errors.
- A quiet test tone produced a nonzero music meter; capture stopped on mode change.
- Hyprland activity events reached the service; next/previous bindings are active
  and `hyprctl configerrors` is empty.
- Focus transitions, Morse overlays, alert restoration, and brightness zero
  were checked against the running service.
- A wrapped command retained exit code 7. Completion alerts work in both an
  isolated interactive Bash and the user's complete Bash startup. Sourcing the
  integration twice installs only one prompt hook.
- The systemd user unit validates and is enabled for graphical-session startup.

Run the pure effect tests from the repository root:

```sh
python3 optional/keyboard-glow/tests/test_effects.py
```

With the same version installed and the service running, the integration checks
are available below. They temporarily change lighting, restore the base mode,
and exercise the actual user session. `check_music.py` also plays a one-second
quiet tone. Run these while no focus timer or temporary alert needs preserving:

```sh
python3 optional/keyboard-glow/tests/check_live.py
python3 optional/keyboard-glow/tests/check_shell.py --full
python3 optional/keyboard-glow/tests/check_music.py
```

Physical Fn+F4 presses and visible aesthetics remain for the user to evaluate.
